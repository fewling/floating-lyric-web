## Actual browser and review results

[Browser evidence](browser-results.json) records 18 November 2026 runs using Playwright 1.65.1, axe-core 4.14.1 / @axe-core/playwright 4.14.0, and installed headless Chrome 157.0.8103.79. The matrix covers five routes at 320, 360, 768 and 1440 CSS pixels in dark and light themes. All 40 returned HTTP 200, one H1/main landmark, and no horizontal page overflow. No-JS pages retained essential explanations and footer support; desktop retained both QR and direct Play route. The live download was not installed by browser automation.

Actual mobile keyboard behavior: Home skip → next Tab lands the main Play badge; all four prose skip links similarly bypass header and reach a main-content link. Menu keyboard activation reaches setup, then LRC and support/privacy. The original sample link generated a successful browser download named `First Light - Floating Lyrics.lrc`; its HTTP contents contain the expected timestamp. Account deletion mailto destination/subject matched the fixed public address. Enter/Space toggled FAQ details, with a computed focus ring. Keyboard activation of the main Play badge opened the exact intended destination, intercepted locally to avoid depending on a store network response. The separate real listing smoke is recorded above. Reduced-motion state had no video/audio or running animation after short interaction-triggered transitions settled.

The initial matrix exposed insufficient light-theme contrast on three step numerals. Review fix `85cc15a` changed their color to full accent, then the complete matrix was rerun with zero axe violations. No other automated violation was suppressed. Axe still returns **incomplete**, rather than passed, color-contrast results for hero heading/subhead against overlapping blurred backgrounds and music/down-arrow glyphs; exact selectors, HTML and reasons remain in the retained browser JSON.

A supplemental rendered-background measurement resolves the heading/subhead cases for the checked viewport/theme combinations. It temporarily hid text while preserving geometry, captured every background pixel in each exact text box, and calculated nominal foreground contrast against each pixel using sRGB relative luminance. [Retained measurements](hero-contrast-results.json) show minimum dark heading foreground 13.18:1 / accent 8.27:1 and subhead 5.72:1; light heading foreground 13.91:1 / accent 3.92:1 and subhead 4.80:1. The heading is large bold text (minimum 36px), so its threshold is 3:1; subhead exceeds the normal-text 4.5:1 threshold. This is scoped rendered-contrast evidence, not complete accessibility certification; decorative glyphs and real screen-reader operation still need human review.

Root reviewed final desktop light customization examples and earlier desktop dark/mobile dark/setup light screenshots and found no visible readability/layout issue. Its CUA interactive host was unavailable, so this was screenshot review, not successful interactive CUA or screen-reader testing. Full-quality retained samples are [desktop light](home-1440-light.png) and [mobile dark](home-390-dark.png). Do not interpret full-page screenshot positions of sticky elements as their ordinary viewport positions.

Independent targeted standards and specification rereviews of `fa21e74..85cc15a` reported zero remaining actionable findings. The earlier content-layer and customization-example findings were addressed. Those read-only reviews did not themselves repeat browser tests or approve outstanding release/launch gates.
